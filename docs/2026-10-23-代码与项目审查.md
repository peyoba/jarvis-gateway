### F01 · 缺失鉴权环境变量时静默关闭鉴权

**位置**：`src/jarvis_gateway/config.py:77–85`；`server/server.py:53,187–194`；`jarvis:464–477`。

`expand_env()` 把缺失变量展开为 `""`。配置 `host=0.0.0.0`、`auth_token=${JARVIS_AUTH_TOKEN}`，但启动环境没有该变量时，服务只输出警告，仍继续运行。

- **动态复现**：临时配置引用不存在的测试变量，加载结果为 `host=0.0.0.0`、`authentication_disabled=true`。
- **现实触发场景**：按 README 在终端 export 令牌后启用登录自启。生成的 LaunchAgent 仅设置 PATH 与 PYTHONUNBUFFERED，没有提供令牌，不能假定它继承交互式终端的环境。经 Finder 启动 App 同样不能假定继承 shell 环境。
- **影响**：原本打算启用鉴权的网关，可能在局域网无鉴权开放；能否执行光标或系统动作还取决于本机权限。
- **建议**：显式引用但缺失的安全变量应报错退出；非回环监听默认要求非空令牌，确需无鉴权时通过明确的危险开关启用；补齐配置类型校验。
- **验收**：缺失 / 空值的必需令牌令进程非零退出，且不留下已启动的子服务；终端、LaunchAgent、App 三条入口分别验证。

### F02 · WAV 解码可绕过上传大小限制

**位置**：`audio/converter.py:44–62`；`server/handler.py:340–356`。

HTTP 层限制 8 MiB 上传，但 WAV 转换信任文件声明的采样率，并据此分配重采样数组，没有时长或输出字节上限。

- **动态复现**：合法、采样率 1 Hz 的 **172 字节 WAV** 被转换为 **2,048,000 字节 PCM**；PCM 膨胀倍数为 16,000。
- **影响**：接近上传上限的类似输入理论上可要求约 **125 GiB** 的输出 PCM，尚未计入中间副本，导致 CPU / 内存耗尽。没有进行真实的大内存攻击。
- **边界**：请求仍受已配置鉴权保护；默认本机客户端或无鉴权 LAN 客户端可以到达该解析路径。
- **建议**：读取 WAV 参数后、分配数组前，限制采样率、声道、帧数、时长、预测解码字节数；按解码后的音频继续执行统一大小限制。
- **验收**：极低采样率、超长时长、异常声道等小文件快速返回 4xx，内存占用有明确上限。

### F03 · 麦克风启动竞争与音轨泄漏

**位置**：`web/dashboard.html:337–373,383–385,434–450`。

`isRecording` 在 `await getUserMedia()` 完成后才置为 true；等待期间释放按键会被 `stopRecording()` 忽略，重复 keydown 也能重复发起启动。

- **JavaScript 模拟复现**：先按下、再松开、最后批准麦克风权限，结果仍是 `recording=true`、音轨未停止。
- 连续三次启动请求完成后再停止，只关闭最后一个全局 `micStream`，**仍留下两条音轨**。
- 未处理 blur、失去可见性、touchcancel 等退出场景，也没有最大录音时长。
- **影响**：录音持续时间违背按住说话的预期；内存持续积累。此处证实的是持续采集，不是自动上传泄露。
- **建议 / 验收**：建立 idle / requesting / recording / uploading 状态机，记录按键是否仍按下，异步返回时校验代次并释放过期流；覆盖提前松开、拒绝权限、重复按键、失焦和时长上限。任何退出路径都必须停止全部音轨。

### F04 · 原字模式的普通口述被误当命令

**位置**：`server/handler.py:398–423`。

`startswith()` 接受没有分隔符的“打字、整理、改写”等常用词，并且优先于当前 raw 模式。

- **HTTP + 模拟 ASR 复现**：“打字速度比以前快了”实际变成“速度比以前快了”。
- raw 模式口述“整理一下今天的会议纪要”，会调用 `polish_text("一下今天的会议纪要")`。
- **影响**：删字、意外润色；如果配置了云模型，正常原字听写也可能被送入该模型，不符合用户对 raw 的直觉。
- **建议 / 验收**：仅接受有明确边界、可配置的口述控制语法；“打字速度、整理资料、改写需求”等普通句子在 raw 模式应完整上屏，且 LLM 调用次数为零。保留明确“润色：……”覆盖行为时，应明确文档与隐私边界。

### F05 · 幻觉过滤误杀真实文本

**位置**：`asr/manager.py:28–32,40–55`。

`len(t) <= 1` 无条件拒绝单字；“谢谢 / 感谢……”规则按句首匹配，和注释所述整句匹配不一致。

- **动态复现**：ASR 已返回“好”，仍被替换为“我没有听清”；短录音中的“谢谢大家的帮助，我明天继续整理文档”也整句丢失。
- **建议**：收紧到完整已知伪句；结合静音、置信度等信号，而不是无条件丢弃单字和包含致谢的有效句子。
- **验收**：覆盖“好、是、一”和带正常后续内容的致谢句，同时保留无声音频伪识别的回归样本。

### F06 · 剪贴板恢复覆盖用户的新内容

**位置**：`actions/injector.py:84–89,111–140`。

恢复定时器只使用进程内部锁，未检查用户是否在等待期间进行了新的复制。

- **纯模拟复现**：原剪贴板 A → 注入文本 → 用户复制 B → 定时恢复，最终得到 **A 而不是 B**。
- **影响**：破坏用户刚复制的内容。“线程安全”不等于和系统剪贴板的其他写入原子协调。
- **建议**：记录 `NSPasteboard.changeCount` 或本次写入标识，只有剪贴板仍由本次注入占有时才恢复；需要完整保留富文本时备份全部格式，而不只是 pbpaste 的纯文本。
- **验收**：用户复制 B 后不能被恢复任务覆盖；连续注入、图片、富文本、超时与失败路径均需回归。

### F07 · 注入失败仍被当成上屏成功

**位置**：`server/handler.py:409–413,458–464,508–527`；`web/dashboard.html:263,401–409`。

即使 `inject_text()` 返回 false，`typed` 仍填待输入内容，记录的 `kind` 仍是 `"ok"`；网页只检查 HTTP 200，不解析二进制元数据。

- **动态复现**：回复虽然包含“键入失败”，但 `typed` 仍非空、最近记录为 `kind=ok`。
- **用户可见后果**：最近记录优先显示“⌨ 文本”，网页麦克风提示“已完成”，掩盖辅助功能权限等实际失败。
- **建议 / 验收**：区分 attempted_text、实际 typed、成功状态和错误原因；失败时 typed 为空、错误计数增加，网页解析元数据并明确显示失败。并非必须把所有业务失败一律改成 HTTP 500。

### F08 · 菜单栏与 CLI 状态查询没有适配配置

**位置**：`build/main.swift:189–225,244–246`；`jarvis:134–139,370–409`。

- **源码确认**：App 固定请求 `127.0.0.1:18888/status`，没有访问令牌；而服务已在鉴权启用时保护 `/status`。
- 401 的 JSON 没有 gateway 字段，`apply()` 将其当“网关未启动”，并据此禁用停止 / 重启菜单。
- 自定义 gateway.port 后，App 状态与打开控制台仍访问旧端口。
- CLI `status` 也没有向 `/status` 携带令牌：`/ping` 可以判在线，但模式、PID、Token 等详情缺失。
- **建议 / 验收**：共享配置与 URL / 鉴权解析，或提供专门的 CLI JSON 状态入口；区分离线、未鉴权、预热。验证“自定义端口 + 令牌 + App 启停”组合。**本次未进行菜单栏真实点击验收。**

### F09 · 未识别进程仍会被终止

**位置**：`jarvis:164–198`。

`pid_command()` 返回空值时，代码直接把监听者当成自身服务；非空时也只是判断完整命令行是否包含 jarvis / whisper 等子串。

- **纯模拟复现**：端口返回 PID，但命令行为空，仍向该 PID 发送 SIGTERM；没有操作任何真实进程。
- **影响**：`start / stop / restart` 在 ps 失败、信息受限等情况下可能终止不属于本项目的进程。
- **建议 / 验收**：无法证明身份时拒绝操作；联合核对受管 PID、启动时间、实际程序与项目路径，避免 PID 复用；显式 takeover / force 另行确认。未知监听者和“仅名称相似”的监听者都应保留。

### F10 · 启动生命周期不完整

**位置**：`jarvis:253–260,295–327`。

通过模拟进程确认了三种情况：

1. 网关端口就绪、Whisper 预热超时，仍输出“已启动”，退出码 **0**。
2. 网关启动失败返回 **1**，但没有终止本次启动的子进程，保留两个 PID 文件。
3. 网关已在线但 Whisper 已缺失，执行 `start` 直接返回 **0**，没有补拉 ASR。

**建议 / 验收**：分组件幂等启动；以各组件健康状态决定结果，而不是仅探测端口；失败时只回滚本次新建进程并清理 PID。增加进程提前退出、端口冲突、模型失败、部分已启动等场景。

### F11 · 轮换模式的接口契约不一致

**位置**：`README_zh.md:182`；`server/handler.py:218–223,320–326`。

- 文档声明 `POST /toggle-mode`，实际仅 GET 实现；动态请求 POST 返回 **404**。
- **建议 / 验收**：实现受鉴权保护的 POST 路由，并补契约测试；已有 GET 写操作进入明确的兼容 / 废弃流程，不应继续作为主要写接口。**修复后**：POST 已实现且受 Origin/Host/令牌保护；GET 写操作返回 405。

### F12 · OpenToken 失败不会切换本地估算

**位置**：`services/token_service.py:71–85,131–171`。

本地计数仅在 `opentoken_bin` 不存在时执行；二进制存在但调用失败 / 解析失败 / 没有当天结果时，既拿不到外部结果，也不累计本地结果。

- **动态复现**：模拟已安装但失效的 OpenToken，调用 `add_local_tokens(100)` 后 total 仍为 **0**。
- **建议 / 验收**：分别维护本地估算与外部数据、外部健康状态和更新时间，按有效性选择展示，明确过期 / 不可用，不要把失败显示成零消耗。外部恢复后也不能双计。
- 额外边界：当前本地估算是内存中的粗略字符估算，没有跨日重置或持久化，不能当作准确账单。

### F13 · 并发请求颠倒听写顺序

**位置**：`server/server.py:28–36`；`server/handler.py:368–498`；`actions/injector.py:104–142`。

请求在线程中各自完成 ASR / LLM，只有最终剪贴板操作加锁，没有按输入顺序协调。

- **动态复现**：第一段较长 auto 请求等待润色，第二段短 auto 请求先完成，实际调用注入顺序为 **第二段 → 第一段**。
- 网页上传期间没有禁用下一次录音，因此单用户也可以遇到，不限于多个设备。
- **资源边界**：服务器还没有应用级并发 / 队列上限；单请求 8 MiB 限制并不限制总体在途内存或 ASR / LLM 并发数。
- **建议 / 验收**：使用有界任务队列，按会话或桌面输入顺序串行提交结果，或明确拒绝 busy 请求；压力测试验证顺序、最大在途任务数和资源上限。

### F14 · 完整听写内容默认落盘，日志只在启动时轮转

**位置**：`asr/manager.py:78,87`；`llm/client.py:96,140`；`actions/injector.py:99–102`；`server/handler.py:526`；`jarvis:214–230`。

- **源码确认**：识别文本、润色结果、注入内容与回复均直接输出；启动器将 stdout / stderr 追加到日志。
- 5 MiB 轮转只在 `spawn()` 执行时检查，长时间不重启仍可无限增长。
- 当前本地网关日志权限为 `0644`；其他账户是否可读还受父目录权限与 macOS 控制影响，不能据此声称已经发生泄露。
- **影响**：敏感口述被长期保留，和“音频不出本机”是不同的隐私边界；目前没有观察到真实密钥被记录的证据。
- **建议 / 验收**：默认记录阶段、耗时、错误码和请求 ID，而非正文；内容日志显式 opt-in，默认 0600，运行中滚动并设置保留策略。用合成敏感样本确认默认日志不含正文。

### F15 · 停止服务后套接字没有释放

**位置**：`server/server.py:143–155,197–200`。

- 只调用 `shutdown()`，没有 `server_close()`。
- **隔离复现**：请求循环线程已经退出，尝试重新绑定同一个随机端口仍失败；显式 `server_close()` 后可清理。
- **影响范围**：主要是同进程嵌入、测试与后续重启逻辑。整个进程退出时 OS 会回收套接字，因此没有把它列为 P1 / P2。
- **建议 / 验收**：幂等关闭主 / 兼容监听器并等待工作线程；停止后端口可重新绑定。

### F16 · App 发布元数据不一致

**位置**：`build/Info.plist:21–26`；`build_app.sh:27–34`。

- Python 版本为 2.3.1，但受 Git 管理的 Info.plist 仍是 **2.3.0**；重新运行构建脚本会再次带入旧版本。
- Info.plist 声称最低 macOS **12.0**，Swift 编译目标却是 **13.0**。
- 本地已有、被忽略的 App 标记为 2.3.1，**不能代表从干净检出重建也会得到相同元数据**。
- **建议 / 验收**：版本号与最低系统版本各自保持单一来源，构建时生成 / 校验；从干净检出构建并检查 plist 与 Mach-O deployment target。

### F17 · Origin 未校验的条件性 CSRF 风险

**位置**：`server/handler.py:73–75,106–114,194–223,278–300`。

只判断 `Sec-Fetch-Site == cross-site`，不检查 Origin，也把同站不同源一律放过；还保留可通过 GET 触发的状态变更。

- **协议层动态复现**：鉴权未开启，带外站 Origin、但没有 Fetch Metadata 的 URL-encoded `POST /mode` 返回 **200** 并改变模式。
- **触发条件**：没有令牌保护，并且浏览器 / 嵌入式 WebView 没有发送相应 Fetch Metadata。启用了正确令牌、或现代浏览器正常发送 cross-site 时，已有机制可以阻止这类请求。
- **验收边界**：这是已经确认的服务端校验缺口，**不是已经验证的“所有现代浏览器都能被利用”**。本次未在真实浏览器中进行跨站利用。
- **建议 / 验收**：浏览器写请求核验严格同源 Origin，保留对无 Origin 的硬件客户端的明确认证规则；主要写操作改 POST，增加外站 Origin、同站不同端口、null Origin 和缺失 Fetch Metadata 的测试。

## 架构、工程与发布建议

### 保留现有模块划分，不做“大重写”

音频、ASR、TTS、LLM、动作和服务的目录边界是合理的。当前主要维护成本集中在 `JarvisHTTPHandler._do_post()`：网络解析、音频校验、意图判定、模型调用、系统副作用、TTS、协议编码和统计都混在同一方法里，而且注入分支大量重复。

建议只做以下定向拆分：

1. 纯 `IntentRouter`：输入模式、时长与识别文本，输出结构化意图，不执行系统动作。
2. `TurnProcessor`：统一队列、deadline、后端回退与结构化执行结果。
3. `WireCodec`：统一正常 / miss / error 的元数据和二进制响应。
4. 薄 HTTP handler：Host / Origin / 鉴权、输入限制、调用处理器、发送响应。
5. 配置、令牌、服务地址与状态协议供 CLI / App / 网页共享，而不是各自猜测。

### 测试优先补真实行为契约

- 把本次探针转成 pytest 回归测试，而不是仅增加格式 / 打包测试。
- 音频 POST 必须覆盖 auto / raw / polish / dialog、明确口述覆盖、唤醒词、识别 miss、LLM 双失败、注入失败。
- 增加配置安全、解码上限、并发顺序、剪贴板竞争和启动器回滚测试。
- 用假的 ASR / LLM / TTS / 动作执行器保持日常 CI 无害、确定；单独设置显式 opt-in 的本机 ASR / TTS 冒烟测试。
- 目前 `test_wire_protocol.py` 只是自行 pack / unpack 数据，不会发现生产 handler 的字段遗漏或失败语义错误；应直接测试真实响应。
- CI 增加 wheel 安装后入口 / dashboard 资源验证、Swift 检查、JavaScript 状态机测试与按核心模块设定的覆盖门禁。

### 其他非阻断改进

- **LLM deadline**：本机 OpenAI SDK 客户端实际 `max_retries=2`。配置的 8 秒不是整个业务操作的 8 秒截止时间；重试和双通道回退会累加。明确 max_retries、总 deadline 与客户端取消策略。
- **网页反馈**：网页没有消费返回的 PCM；若声称完整支持浏览器语音问答，需要补音频播放、自动播放限制处理，以及回复 / 失败的明确展示。
- **依赖治理**：保留用户依赖的合理范围，同时为开发 / 发布验证固定一组可复现依赖；当前仅有 `openai>=1.0.0`，本次验证的是本机安装版本，不是所有允许版本。
- **发布自动化**：将构建、安装冒烟、版本一致性和资源检查纳入发布门禁，避免只运行 editable install 的 CI。
- **安装文档**：补充 wheel 安装后的 `jarvis-gateway --config ...` 用法、Whisper 需独立启动的边界，以及 App 依赖完整 checkout / venv 的事实。修复前 sdist 不包含根目录启动器、配置模板和菜单栏源码；修复后已通过 `MANIFEST.in` 与独立 Python 构建目录保留这些源码，但仍不捆绑 venv、Whisper 模型和本机私有配置。
- **安全说明**：补 `SECURITY.md`、支持版本、私密报告渠道；清楚区分本地音频、云端文本、磁盘日志、令牌和 LAN 明文 HTTP 的边界。LAN 之外使用受保护的 TLS / VPN，不把 Host 校验当作认证。
